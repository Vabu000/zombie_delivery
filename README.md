## 🧟 Про проект та предметну область
В умовах зомбі-апокаліпсису пересування містом у нічні години смертельно небезпечне для живих людей. Сервіс **Zombie Night Delivery Aggregator** надає платформу для:
- **Клієнтів-виживаючих (Survivor)**: замовлення доставки життєво необхідних ресурсів (плазма, медикаменти, консерви, антидоти) до укріплених бункерів.
- **Зомбі-кур'єрів (Night Hunters)**: виконання рейсів крізь заражені зони за винагороду в раціонах (`reward_brains`).
- **Адміністраторів (Hive Overlord)**: глобальний моніторинг маршрутів, рівнів загроз зон (`LOW`, `MEDIUM`, `HIGH`, `NIGHTMARE`) та керування доступом.

> Детальніше див. у файлі [docs/domain_choice.md](docs/domain_choice.md).

## 🏛️ Архітектура системи
Система спроєктована за багатошаровою архітектурою:
- **Presentation Tier**: Веб-дашборди клієнтів, кур'єрів та адміністратора (`/dashboard/`), Swagger UI (`/docs`).
- **Gateway & Load Balancer**: Nginx (SSL termination, Round-Robin балансування, Rate Limiting).
- **Application Tier**: FastAPI + Uvicorn асинхронні воркери, Pydantic v2 валідація, JWT аутентифікація.
- **Cache Tier**: Redis для кешування гарячого пулу замовлень та розподілених блокувань.
- **Persistence Tier**: Повна ізоляція даних між Sandbox (`sandbox.db`) та Production (`production.db`).

> Детальний архітектурний опис та діаграми C4: [docs/architecture.md](docs/architecture.md)
> Графічна векторна діаграма архітектури: [docs/architecture_diagram.svg](docs/architecture_diagram.svg)

## 🛡️ Ролі користувачів та безпека
1. **Ролі (RBAC)**:
   - `user`: створення власних замовлень, перегляд виключно своїх доставок, оновлення особистого профілю.
   - `courier`: перегляд пулу доступних замовлень (`PENDING`), взяття в рейс (`claim`), завершення доставки (`complete`).
   - `admin`: необмежений моніторинг усіх доставок, доступ до адмін-панелі (`/users/admin-panel`), глобальне керування.
2. **Захист від IDOR (Insecure Direct Object References)**:
   - Спроба користувача переглянути, відредагувати чи скасувати чужу доставку блокується зі статус-кодом `403 Forbidden`.
   - Спроба користувача змінити чужий профіль (`PUT /users/{id}`) блокується зі статус-кодом `403 Forbidden`.
3. **Безпека Production (DEBUG=False)**:
   - При виникненні внутрішньої помилки 500 користувачу віддається безпечне повідомлення без витоку стектрейсів чи структури коду.

## 🧪 Запуск у Sandbox (Тестове середовище)
У режимі Sandbox:
- Змінні завантажуються з `.env.sandbox`
- База даних: `sandbox.db`
- `DEBUG=True` (детальні помилки для відладки)

**Windows PowerShell:**
```powershell
$env:ENV="sandbox"
uvicorn src.main:app --reload --port 8000
```

**Linux / macOS:**
```bash
export ENV=sandbox
uvicorn src.main:app --reload --port 8000
```

---

## 🚀 Запуск у Production (Робоче середовище)
У режимі Production:
- Змінні завантажуються з `.env.production`
- База даних: `production.db` (ізольована від sandbox)
- `DEBUG=False` (стектрейси помилок 500 приховані)

**Windows PowerShell:**
```powershell
$env:ENV="production"
uvicorn src.main:app --port 8000
```

**Linux / macOS:**
```bash
export ENV=production
uvicorn src.main:app --port 8000 --workers 4
```

Після запуску відкрийте браузер:
- Головний портал / дашборди-заглушки: [http://localhost:8000/dashboard/](http://localhost:8000/dashboard/)
- Інтерактивна документація Swagger UI: [http://localhost:8000/docs](http://localhost:8000/docs)
- Альтернативна документація ReDoc: [http://localhost:8000/redoc](http://localhost:8000/redoc)

## 🧪 Тестування (Pytest)
Проєкт містить повне покриття юніт- та інтеграційними тестами:
- **Анонімний доступ (401 Unauthorized)**
- **Успішна автентифікація та помилки входу (200 / 401)**
- **Вертикальне розмежування ролей (403 Forbidden / 200)**
- **Горизонтальне розмежування прав IDOR (403 Forbidden)**
- **Базова бізнес-логіка MVP доставок (розрахунок винагороди, claim, complete)**
- **Безпека 500 помилок та ізоляція конфігурації**

Запуск тестів:
```bash
pytest tests/ -v
```

## 🔄 CI/CD Пайплайн
Налаштовано GitHub Actions workflow (`.github/workflows/main.yml`), який автоматично запускається при кожному `push` та `pull_request` на гілки `main` та `master`.
Пайплайн виконує:
1. Перевірку синтаксису та лінтинг: `ruff check .`
2. Перевірку форматування: `ruff format --check .`
3. Автоматичний прогін усіх тестів: `pytest tests/ -v`
